1) Create `requirements-prod.txt`
- Copy only runtime dependencies (exclude dev/test tools like `pytest`, `tox`, etc.)
- Build PyInstaller from a clean venv installed from `requirements-prod.txt` to shrink `PYZ-00.pyz` contents.


2) Prune PyInstaller `spec` (use `excludes` and explicit `datas`)
- Exclude unused Qt modules that PySide6 may drag in: common candidates:
  - `PySide6.QtWebEngineWidgets`, `PySide6.QtQml`, `PySide6.QtQuick`, `PySide6.QtWebChannel`, `PySide6.QtWebEngineCore`.
- Example `Analysis(..., excludes=[...])` snippet to add to `NOTG-Launcher.spec`:

3) Use `--strip` and optionally UPX (test carefully)
- `--strip` reduces binary size (strip symbols) and works well on Unix; on Windows, `strip` may be limited.
- UPX can compress many binaries; exclude core Qt DLLs  UPX causes runtime issues. Always test the packaged app thoroughly.

4) Make heavy optional libs lazy-imported
- If your app uses optional features (e.g., `yt_dlp` or optional tools), import them only inside the functions that need them. This prevents PyInstaller from including them in `PYZ` unless those code paths are included by analysis.

Reliability, Observability & Diagnostics
1) Add rotating logs
- Use `logging.handlers.RotatingFileHandler` and `platformdirs.PlatformDirs` to place logs in the proper OS location.
```python
import logging
from logging.handlers import RotatingFileHandler
from platformdirs import PlatformDirs
from pathlib import Path

dirs = PlatformDirs(appname="NOTG Launcher", appauthor=False)
log_file = Path(dirs.user_log_dir) / "notg-launcher.log"
log_file.parent.mkdir(parents=True, exist_ok=True)
handler = RotatingFileHandler(log_file, maxBytes=5*1024*1024, backupCount=5, encoding='utf-8')
logging.basicConfig(level=logging.INFO, handlers=[handler])
```
2) Use `logger.exception()` in except blocks so stack traces are captured.
3) Add health/telemetry hooks (local logs only) to capture update failures, installer errors, and session-monitor exits.

Testing & Verification Steps
- Static checks:
  - `python -m py_compile app/core/updater.py` (and other modified modules)
  - `flake8` or `ruff` (optional) for style and potential mistakes.
- Unit/Integration tests:
  - Run `pytest -q` and fix failures in small iterative commits.
- Manual verification after each critical change:
  - Start the app and run the updater against a controlled test ZIP.
  - Validate UI flows affected by network work are responsive and error-handling works.
- Profiling to measure impact:
  - `py-spy` (sampling profiler) is non-invasive for production builds:
    - `py-spy record -o profile.svg -- .venv\Scripts\python.exe app\main.py`
  - Or use built-in `cProfile` for targeted functions.
